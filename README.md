## 2. 시나리오 (5~10줄)

<br>
이 프로그램은 현대 사회의 경제 활동에 필수적인 **'개인별 신용 등급'**을 체계적으로 판독하고 관리하는 스마트 금융 시스템입니다. 
가장 먼저 시스템을 방문한 사용자에게 이름과 현재 연봉, 보유하고 있는 부채(빚), 그리고 지난 한 해 동안의 연체 횟수와 같은 금융 데이터를 정중하게 물어보고 그 대답을 변수에 기록하는 것으로 서비스가 시작됩니다. 그다음에는 사용자가 대답한 수치들을 금융 공학적 로직에 대입하여 이 사용자의 경제적 신뢰도가 어느 정도인지 **'최종 신용 점수'**로 환산해 봅니다. 이렇게 계산된 신용 점수가 기준치보다 높으면 우량 고객인 '1등급' 판정을 내리고 대출 우대 혜택을 안내하지만, 점수가 낮으면 주의가 필요한 '저신용' 등급으로 분류하여 개선 권고를 해줍니다. 만약 연봉이 매우 높으면서도 연체 횟수가 0회인 아주 성실한 고객이 있다면, **'VVIP 마스터'**라는 특별한 칭호와 함께 특별 한도 상향이라는 깜짝 혜택까지 제공할 계획입니다. 나중에는 한 명의 데이터만 처리하는 것이 아니라, 우리 시스템을 거쳐 간 **수많은 고객의 정보를 커다란 데이터 주머니(리스트)**에 차곡차곡 담아서 관리하고, 관리자가 원할 때마다 전체 고객 명부와 등급 현황을 한눈에 꺼내 볼 수 있게 만들 것입니다. 마지막으로 이 모든 기능은 사용자가 화면에 뜨는 메뉴판에서 번호를 눌러 자유롭게 선택할 수 있고, **'시스템 종료'**를 선택하기 전까지는 계속해서 새로운 고객의 등급을 판독할 수 있는 전문적인 콘솔 기반 금융 소프트웨어로 완성될 계획입니다.

### **✨2차 과제 내용:**
개인별 금융 데이터 등록 및 신용 등급 정밀 판독 시스템 구현으로, 사용자로부터 경제 지표 데이터를 입력받아 리스트에 저장하고, 금융 공학적 가중치 연산을 통해 최종 신용 점수를 도출하는 시스템을 구축하는 것입니다. 특히 if-elif 조건문과 and/or 논리 연산자를 활용하여 신뢰 등급을 분류하고, 특정 조건을 만족하는 우량 고객에게 **'VVIP 마스터'**와 같은 특별 칭호를 부여하는 지능형 금융 로직을 완성하는 데 중점을 두었습니다.데이터 수집: input()으로 고객의 이름, 연봉, 총 부채, 연체 횟수를 입력받아 리스트에 저장.신용 점수 산출: 금융 가중치 공식을 적용하여 종합 신용 점수 산출:$Score = ( 연봉 \times 0.6 ) - ( 부채 \times 0.25 ) - ( 연체 횟수 \times 150 )$등급 판정: if-elif-else를 사용하여 1등급(우량)부터 5등급(위험)까지 5단계 등급 판정 로직 추가.특별 혜택 부여: and 연산자를 활용하여 '연봉 1억 이상'이면서 '연체 횟수 0회'인 경우 'VVIP 마스터' 칭호와 한도 상향 혜택 부여 기능 구현.

🛠️ Trouble Shooting (예상 문제 및 해결 방안)
1. 입력 값의 형변환(Casting) 오류

문제: input()으로 받은 연봉과 부채가 문자열(str)이라서 가중치 곱셈 연산 시 에러가 발생하거나 글자가 반복되는 현상이 나타남.

해결: int(input())을 사용하여 입력 단계에서 즉시 정수형으로 변환하여 산술 연산이 가능하도록 해결함.

2. 논리 연산자의 우선순위 혼동

문제: VVIP 조건을 체크할 때 연봉 > 10000 or 연체 == 0으로 작성하여, 연봉만 높으면 연체가 많아도 VVIP가 되는 논리적 허점이 발견됨.

해결: 두 조건을 모두 만족해야 하는 금융 원칙에 따라 or를 and 연산자로 수정하여 엄격한 심사 로직을 구현함.

3. 점수 하한선 및 상한선 설정

문제: 부채가 너무 많으면 신용 점수가 마이너스(-)가 나오는 비현실적인 상황 발생.

해결: if score < 0: score = 0 로직을 추가하여 점수가 0점 밑으로 떨어지지 않게 보정하는 '데이터 정규화' 과정을 거침.

## 🟨 [3차 과제: V3.0] 무한 루프와 메뉴 시스템 (반복문) - 향후 작성 예정

또한 for문과 range()를 조합하여 전체 데이터의 규칙적인 탐색 및 검색을 가능하게 만들었으며, 사용자가 입력한 번호에 따라 [1. 신규 고객 정보 등록], [2. 전체 고객 명부 조회], [3. 특정 고객 검색], [5. 시스템 업무 종료] 등의 분기 처리가 유기적으로 작동하는 실전형 인터페이스를 구축하는 데 중점을 두었습니다.
    
### **🤖 AI 파트너십 과정**
 1.내용 1 : 효율적인 무한 루프 탈출(Break) 조건 및 구조 설계

프롬프트 요약: "while True 무한 루프 안에서 사용자가 종료를 원할 때 안전하게 프로그램을 종료하고, 잘못된 메뉴 번호를 누르면 다시 메뉴판을 보여주는 구조를 어떻게 짜야 할까?"

적용 내용: 사용자가 종료 번호(예: 5번)를 입력했을 때만 break문이 작동하여 안전하게 루프를 탈출하도록 설계함. 또한 메뉴 범위(1~5)를 벗어난 값이 입력되면 else 구문을 통해 "잘못된 번호입니다"라는 경고 메시지와 함께 메뉴판이 무한 재출력되는 방어적 인터페이스를 확립함.

내용 2 : 중첩 리스트 기반의 2차원 데이터 검색 로직 최적화

적용 내용: AI가 제안한 for customer in customer_db: 형태의 순회 알고리즘을 자문받아 적용함. 이를 통해 전체 명부를 하나씩 대조하며 사용자가 찾는 이름이 존재할 경우 해당 고객의 신용 등급과 점수를 콕 집어 보여주는 '특정 고객 검색 및 관리' 기능을 성공적으로 구현함.
    
### **🛠️ Troubleshooting & 기술 회고:**
  1문제 1: 무한 루프 내 데이터 초기화 현상

원인: while True: 루프가 시작되는 내부(Loop Body)에 customer_db = [] 리스트를 선언하는 바람에, 새로운 고객을 등록하고 메뉴를 한 바퀴 돌 때마다 리스트가 계속 빈 상태로 초기화되어 기존 데이터가 증발하는 현상이 발생함.

해결: 리스트 선언문(customer_db = [])을 while 반복문이 시작되기 전인 프로그램 최상단(루프 외부)으로 이동시켜, 프로그램이 켜져 있는 동안 데이터가 누적되어 저장되도록 메모리 유지 메커니즘을 수정함.

문제 2: 고객 검색 실패 시 예외 처리 누락

원인: 데이터베이스에 없는 이름(예: '임꺽정')을 검색했을 때, 프로그램이 아무런 반응을 하지 않거나 루프가 그냥 넘어가 버려 사용자에게 혼란을 주는 UI 결함이 발견됨.

해결: 검색 반복문 진입 전 플래그 변수(found = False)를 설정하고, 일치하는 데이터가 있을 때만 found = True로 변경하는 로직을 추가함. 반복문이 끝난 뒤에도 if not found: 조건에 걸리면 "등록되지 않은 고객입니다"라는 안내 문구를 명확히 출력하도록 보완함.

### **🛠️ Troubleshooting & 기술 회고:**
문제 1:

원인: 함수 내부에서 메인 데이터베이스인 customer_db에 데이터를 추가(append)하거나 수정하려고 할 때, 파이썬이 함수 내부의 지역 변수(Local Variable)로 오인하여 UnboundLocalError가 발생하거나 데이터가 영구적으로 반영되지 않는 문제가 발생함.

해결: 함수 아키텍처를 설계할 때 데이터베이스 자체를 함수의 매개변수로 명시적으로 넘겨주거나, 함수 내부 상단에 global customer_db 키워드를 선언하여 전역에 위치한 데이터 주머니를 정확히 참조하고 수정할 수 있도록 해결함.

문제 2:

원인: 신용 점수를 계산하는 함수에서 열심히 등급과 칭호를 판정해 두고, 정작 호출한 곳으로 결과를 돌려주는 return 문을 작성하지 않아 메인 루프에서 결과를 받아 저장할 때 NoneType 관련 에러(데이터 공백 현상)가 발생하는 허점이 발견됨.

해결: 계산 및 판독 함수 제일 하단에 return [total_score, grade, title]과 같이 필요한 결과물들을 패킹(Packing)하여 호출한 메인 시스템으로 정확히 전달하도록 리턴 로직을 확실하게 보완함.
